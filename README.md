## What is this

**Find your spot in London** — an interactive map to explore amenities, public transport, and neighbourhood context side by side. Pin postcodes, toggle layers, and see how areas compare at a glance.

## What you can do

- **Search postcodes** — jump to an area and keep a shortlist of places you care about.
- **Point layers** — tube and rail, supermarkets and Waitrose, coffee, libraries, pubs, parks, restaurants, GP surgeries, dentists, schools (with latest Ofsted outcome), coworking, gyms, cinemas, bike parking, and more. Each layer can be switched on or off. POIs show as emoji markers on the map.
- **Area layers** — choropleths for crime, air quality (NO₂), house prices, estimated rent, IoD2025 deprivation domains, population density, transport access (TfL PTAL / access index), green space score, modelled noise (Lden), flood risk, and gigabit broadband availability, so you can read "how this patch of the city feels" next to the map.
- **Scorecards** — blended scores for each pinned postcode (proximity + area signals), with short explanations on what each metric means. Disable dimensions you don't care about.
- **Filters** — set thresholds on crime, air quality, house prices, deprivation, population density, noise, flood risk, and minimum transport access, green-space and broadband scores to grey out areas that don't pass.
- **Compare** — pin multiple postcodes and see a side-by-side comparison across all dimensions.
- **Walking rings** — concentric distance rings around pinned postcodes (5/15/30/45 min walk), with each ring labelled on the map.
- **Optional transit isochrones** — public-transit reach from pinned postcodes when the app has a TfL API key configured.
- **Shareable URLs** — app state is encoded in the URL hash: postcodes, active POI layers, selected choropleth, choropleth opacity, walking rings, area filters, disabled scorecard dimensions, and optional transit isochrone visibility.

Data is bundled as static files in the repo (one boundary GeoJSON plus small per-layer value tables; POI GeoJSON is fetched on demand), so the map works offline once built — no database required. The **Data & freshness** panel in the app shows when each layer was last generated.

## Run it locally

```bash
npm install
npm run dev
```

Then open the URL Vite prints (usually `http://localhost:5173`).

## Build for production

```bash
npm run build     # also rebuilds public/data/manifest.json first
npm run preview   # serve the dist/ folder locally
npm test          # vitest: URL state, data join, scoring
npm run lint
```

## Updating bundled data

Files under `public/data/` are generated by Node scripts in `scrapers/`. Run everything from the **repository root** after installing app dependencies (spreadsheet parsing uses **SheetJS** `xlsx`, installed from the [official CDN tarball](https://cdn.sheetjs.com/) — not the stale `xlsx` copy on the public npm registry).

```bash
npm install
```

### File layout

| File | What |
|------|------|
| `public/data/lsoa-boundaries.geojson` | The 4,994 London LSOA (2021) polygons. Fetched once by the app; every area layer joins onto it by `code`. |
| `public/data/<layer>.json` | Area layers: `{ meta, values: { [lsoaCode]: value } }` — no geometry, so each is ~80 KB. |
| `public/data/<layer>.geojson` | Point layers: minified GeoJSON with a `meta` block (source, vintage, generated date, count). Loaded when you toggle the layer or pin a postcode. |
| `public/data/manifest.json` | All `meta` blocks in one place; built by `npm run manifest` (also runs automatically before `npm run build`). Drives the in-app **Data & freshness** panel and the POI counts in the sidebar. |
| `scrapers/.cache/` | Raw downloads (spreadsheets, CSVs, zips). Gitignored; delete a file to force a re-download. |

Every scraper ends by calling `writeAreaLayer` or `writePointLayer` from `scrapers/lib/output.js`, which is what produces the shapes above.

### Automatic monthly refresh

`.github/workflows/refresh-data.yml` reruns the scrapers on the first Monday of each month (or on demand from the Actions tab) and opens a pull request on the `data/monthly-refresh` branch with whatever changed. Overpass-heavy scrapers are allowed to fail individually so one flaky mirror does not block the rest. Review the manifest diff, check a preview deploy, merge.

### Clearing caches (optional)

| File | When to delete it |
|------|-------------------|
| `public/data/lsoa-boundaries.geojson` | You want to **re-download London LSOA polygons** from the ONS ArcGIS services (e.g. after a boundary release). The next area scraper will fetch again. |
| `scrapers/.cache/_iod2025_scores.xlsx` | Re-download the IoD2025 scores spreadsheet (File 5) used by `imd.js` and `rent.js`. |
| `scrapers/.cache/_population-density-ts006.xlsx` | Re-fetch Census 2021 TS006 LSOA population density. |
| `scrapers/.cache/_ptal-lsoa-2023.csv` | Re-fetch TfL LSOA PTAL / access stats. |
| `scrapers/.cache/_hpssa46*` | Re-download the ONS HPSSA dataset 46 house price workbook. |
| `scrapers/.cache/_ofcom-*` | Re-download Ofcom Connected Nations coverage files. |
| `scrapers/.cache/_gias-*`, `_ofsted-*` | Re-download the GIAS schools extract and Ofsted management information (GIAS is refreshed daily; the scraper reuses a copy under 7 days old). |
| `scrapers/.cache/_flood*` | Re-download Environment Agency flood polygons. |

### Area layers (LSOA)

These join or aggregate to the LSOA boundaries. **`crime.js` is slow**: it hits [data.police.uk](https://data.police.uk/) for many grid points with delays between batches — expect several minutes and be gentle on their service.

```bash
node scrapers/imd.js                 # IoD2025 → imd.json (+ caches scrapers/.cache/_iod2025_scores.xlsx)
node scrapers/rent.js                # Modelled est. rent → rent.json (uses the IoD2025 cache)
node scrapers/house-prices.js        # ONS HPSSA 46 median price paid → house-prices.json
node scrapers/air-quality.js         # NO₂ interpolation → air-quality.json
node scrapers/population-density.js  # Census 2021 TS006 → population-density.json
node scrapers/ptal.js                # TfL LSOA access index → ptal.json
node scrapers/noise.js               # IDW from curated Lden points → noise.json
node scrapers/broadband.js           # Ofcom Connected Nations gigabit availability → broadband.json
node scrapers/flood-risk.js          # Environment Agency flood zone share → flood-risk.json
node scrapers/green-space.js         # OSM greenspace → green-space.json (Overpass, multi-bbox; slow)
node scrapers/crime.js               # Latest police month → crime.json (slow)
```

### Point layers

Most come from OpenStreetMap via Overpass; `schools.js` uses the DfE GIAS extract. Respect [Overpass usage](https://wiki.openstreetmap.org/wiki/Overpass_API) (no hammering; try off-peak if a query times out). `scrapers/lib/overpass.js` rotates public instances with retries. **`restaurants.js`, `bike-parking.js` and `green-space.js` are the heaviest.**

```bash
for f in tube-rail waitrose supermarkets coffee libraries pubs parks yoga gyms cinemas bike-parking betting gp-surgeries dentists coworking restaurants; do node scrapers/$f.js; done
node scrapers/schools.js
```

### After scraping

```bash
npm run manifest     # refresh public/data/manifest.json
npm test && npm run build
```

Commit the changed files under `public/data/`, then rebuild or redeploy the site.

## Data sources

Bundled layers are static files under `public/data/`, produced or refreshed by scripts in `scrapers/`. Interpretation here is for exploration only — not planning, legal, or financial advice.

### Map tiles

| What | Source |
|------|--------|
| Basemap | [CARTO](https://carto.com/) "Positron" raster tiles (API key required since Sept 2026); map data © [OpenStreetMap](https://www.openstreetmap.org/copyright) contributors |

### Point layers (POIs)

Unless noted, layers are queried from **OpenStreetMap** via the **[Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)** (community-mapped data; completeness varies by area).

| Layer | Source / OSM tags | Output file |
|-------|-------------------|-------------|
| Tube & Rail | `railway=station`, `station=subway`, `railway=halt`, `station=light_rail` | `tube-rail.geojson` |
| Waitrose | `shop` + `brand` / `name` matching Waitrose | `waitrose.geojson` |
| Supermarkets | `shop=supermarket` (nodes + ways), brand normalised for the big chains | `supermarkets.geojson` |
| Coffee shops | Cafes; chain filter in scraper | `coffee.geojson` |
| Libraries | `amenity=library` | `libraries.geojson` |
| Pubs | `amenity=pub` | `pubs.geojson` |
| Parks & green space | `leisure=park`, `garden`, `nature_reserve` (non-private where tagged) | `parks.geojson` |
| Restaurants | `amenity=restaurant` (named only; London split into bbox shards in scraper) | `restaurants.geojson` |
| GP surgeries | `amenity=doctors`, `healthcare=doctor` | `gp-surgeries.geojson` |
| Dentists | `amenity=dentist`, `healthcare=dentist` | `dentists.geojson` |
| Schools | **DfE [Get Information about Schools](https://get-information-schools.service.gov.uk/Downloads)** (not OSM): open schools in the 33 boroughs, all phases incl. independent; latest outcome joined by URN from [Ofsted management information](https://www.gov.uk/government/statistical-data-sets/monthly-management-information-ofsteds-school-inspections-outcomes) (state-funded only; single-word grades ended Sept 2024, report cards from Nov 2025) | `schools.geojson` |
| Coworking | `amenity=coworking_space`, `office=coworking` | `coworking.geojson` |
| Yoga studios | `leisure=fitness_centre` + `sport=yoga` / name patterns, `sport=yoga`, etc. | `yoga.geojson` |
| Gyms | `leisure=fitness_centre` | `gyms.geojson` |
| Cinemas | `amenity=cinema` | `cinemas.geojson` |
| Bike parking | `amenity=bicycle_parking` | `bike-parking.geojson` |
| Betting shops | `shop=bookmaker` / `betting`, `amenity=gambling` | `betting.geojson` |

### Area layers (LSOA choropleths)

| Layer | Source | Output file |
|-------|--------|-------------|
| **LSOA boundaries** | [ONS Open Geography Portal](https://geoportal.statistics.gov.uk/) — Lower Layer Super Output Areas (2021), filtered to London via LSOA–LAD lookup | `lsoa-boundaries.geojson` |
| **Crime (current)** | [data.police.uk](https://data.police.uk/) street-level crime API, latest published month (grid sampling + assignment to LSOA) | `crime.json` |
| **Air quality (NO₂)** | Published annual mean NO₂ at monitoring sites (London Air / AURN-style figures in `scrapers/air-quality.js`), **inverse-distance interpolated** to LSOA centroids — modelled surface, not a regulatory map | `air-quality.json` |
| **House prices (£)** | [ONS HPSSA dataset 46](https://www.ons.gov.uk/peoplepopulationandcommunity/housing/datasets/medianpricepaidbylowerlayersuperoutputareahpssadataset46) — median price paid by LSOA from HM Land Registry, year ending Mar 2023 (last published edition); 2011 codes mapped to 2021 LSOAs via the ONS lookup, sparse areas backfilled from the previous 3 years or borough median | `house-prices.json` |
| **Est. rent (£/mo)** | **Modelled** in `scrapers/rent.js`: IoD2025 income / housing-barriers signals + hand-tuned borough median anchors → indicative monthly £ per LSOA. **Not** official rents or listings — exploration only | `rent.json` |
| **Deprivation (IoD2025)** | [English Indices of Deprivation 2025](https://www.gov.uk/government/statistics/english-indices-of-deprivation-2025) (MHCLG, Oct 2025) — File 5 scores spreadsheet on 2021 LSOAs, joined directly to LSOA boundaries | `imd.json` |
| **Population density** | [ONS Census 2021 TS006](https://www.ons.gov.uk/datasets/TS006/editions/2021) — usual residents per km² at LSOA; table pulled in `scrapers/population-density.js` via the [UK Data Service CKAN-hosted XLSX](https://statistics.ukdataservice.ac.uk/dataset/ons_2021_demography_population_density) | `population-density.json` |
| **Transport access (PTAL)** | [TfL — LSOA aggregated PTAL stats 2023](https://gis-tfl.opendata.arcgis.com/datasets/3eb38b75667a49df9ef1240e9a197615) (CSV on ArcGIS Hub). Choropleth uses **mean access index (`mean_AI`)**; banded PTAL categories are in the source file | `ptal.json` |
| **Green space score** | **OpenStreetMap** (Overpass): parks, gardens, nature reserves, recreation grounds, village greens — proximity-weighted count near LSOA centroids, then percentile score (exploratory proxy, not official greenspace %). See `scrapers/green-space.js` | `green-space.json` |
| **Noise (Lden)** | **Modelled** in `scrapers/noise.js`: inverse-distance interpolation from hand-picked representative **Lden** (dB) points informed by [Defra strategic noise mapping](https://www.gov.uk/government/collections/strategic-noise-mapping) / London context — not a downloaded Defra raster | `noise.json` |
| **Flood risk (Zone 3)** | **Environment Agency** [Flood Map for Planning – Flood Zones](https://environment.data.gov.uk/dataset/04532375-a198-476e-985e-0579a0a11b47) (OGL v3), WFS; % of each LSOA inside **Flood Zone 3** (≥1-in-100 river / ≥1-in-200 sea annual chance, defences ignored — so the defended Thames corridor still scores high), estimated by point-grid sampling in `scrapers/flood-risk.js` | `flood-risk.json` |
| **Gigabit broadband** | [Ofcom Connected Nations 2025](https://www.ofcom.org.uk/phones-and-broadband/coverage-and-speeds/connected-nations-20252/data-downloads-2025) fixed coverage open data (OGL), July 2025 snapshot — % of premises with gigabit-capable availability, output areas summed to LSOA 2021 via the ONS OA→LSOA lookup (also ≥30 and ≥100 Mbit/s shares) | `broadband.json` |
